\chapter{Test Reproduction Commands}

The commands below must be run from the correct component directory. The person carrying out the test must record the commit, runtime version, provider configuration, and service status; secrets must not be copied into the record.

\begin{verbatim}
cd demo/backend
npm test
npm run test:ai

cd ../frontend
EXPO_PUBLIC_API_URL=http://127.0.0.1:3000 \
  npx expo export --platform web \
  --output-dir /tmp/perfin-web-final
\end{verbatim}

Integration testing requires a dedicated test PostgreSQL instance and a running Redis instance. Migrations must be run against the test database; after each test group, rollback must be verified and data cleaned up using fixtures. A personal development database must never be used as the automated test environment.

\chapter{Demonstration Principles}

\begin{enumerate}
  \item Start with scripted seed data and clearly disclose that it is simulated data.
  \item Demonstrate the same transaction through both the form and chat to quantify the data-entry benefit.
  \item Enter a sentence missing the amount to demonstrate the clarification state and TTL.
  \item Correct the category, then repeat a near-identical sentence to demonstrate feedback retrieval.
  \item Open an insight and display the facts alongside the persona's narrative interpretation at the same time.
  \item Shut down the provider or Redis in a controlled manner to demonstrate that the fallback does not generate mock data.
  \item Do not present auth, bank sync, push notifications, PDF, or backup as completed features when the acceptance criteria have not been met.
\end{enumerate}

\chapter{Stability Criteria for Critical Functions}

Post-report bug-fix priority is determined by the impact on data integrity and on the ability to conduct an academic demo:

\begin{enumerate}
  \item \textbf{P0 --- data integrity:} transactions that do not leak connections, atomic pending confirmation, correct batch rollback, user-scoped IDs.
  \item \textbf{P1 --- input pipeline:} correct amount parsing, correctly stated provider-selector state, stable ordering for clarification and history.
  \item \textbf{P1 --- algorithms:} the timeline retains months with no data, runway correctly handles no-spend days, reports use the correct denominator for the filtered period.
  \item \textbf{P2 --- tasks and media:} atomic recurring payments, worker deduplication, adapters that return genuine errors and have ground truth.
  \item \textbf{P2 --- demo support:} wallet creation on a fresh install, correctly formatted export, and backup/restore that does not retain secret keys in the bundle.
\end{enumerate}

Every fix must have a regression test that fails before the fix and passes after the fix. Only functionality with both an automated test and a reproducible demo flow may be moved from ``target design'' to ``measured''.
