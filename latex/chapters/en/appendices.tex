\chapter{List of Draw.io Diagrams}

The report uses 26 diagrams. The canonical editable sources live in \path{latex/figures/drawio/} and the rendered versions in \path{latex/figures/rendered/}; each basename in the table below corresponds to one \path{.drawio} file in the source directory and three renders named alike (\path{.pdf}, \path{.png}, \path{.svg}). The report links to the vector PDF version; PNG/SVG formats are used for quick viewing and web documentation. All \path{.drawio} files are generated by three Python scripts in the same directory: \path{core_gen.py} produces diagrams 03--12, \path{usecase_gen.py} produces diagrams 14--26, and \path{sequence_style.py} produces the sequence diagrams; a diagram must therefore be changed in its script and regenerated rather than edited directly as XML. Terminology in the diagrams is consistent with the report and clearly distinguishes the deterministic core, the LLM, persistent data, transient state, and external services; every diagram in which colour carries meaning includes a colour legend inside the figure.

\chapter{Test Reproduction Commands}

The commands below must be run from the correct component directory. The person carrying out the test must record the commit, runtime version, provider configuration, and service status; secrets must not be copied into the record.

\begin{verbatim}
cd demo/backend
npm test
npm run test:ai

cd ../frontend
EXPO_PUBLIC_API_URL=http://127.0.0.1:3000 \
  npx expo export --platform web \
  --output-dir /tmp/perfin-web-final
\end{verbatim}

Integration testing requires a dedicated test PostgreSQL instance and a running Redis instance. Migrations must be run against the test database; after each test group, rollback must be verified and data cleaned up using fixtures. A personal development database must never be used as the automated test environment.
