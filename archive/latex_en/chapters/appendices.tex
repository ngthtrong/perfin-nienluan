\chapter{Test Reproduction Commands}

The commands below are run from the corresponding component directory. The person executing them must record the commit, runtime version, provider configuration, and service status; secrets must not be copied into the results record.

\begin{verbatim}
cd demo/backend
npm test
npm run test:ai

cd ../frontend
EXPO_PUBLIC_API_URL=http://127.0.0.1:3000 \
  npx expo export --platform web \
  --output-dir /tmp/perfin-web-final
\end{verbatim}

For integration testing, a dedicated test PostgreSQL instance and a running Redis instance are required. Migrations must be run on the test database; after each test group, rollback must be verified and data cleaned up using fixtures. A personal development database must not be used as an automated environment.

\chapter{Demonstration Guidelines}

\begin{enumerate}
  \item Start with scripted seed data and clearly state that it is simulated data.
  \item Demonstrate the same transaction entered via both form and chat to quantify the data-entry benefit.
  \item Enter a sentence missing the amount to demonstrate the clarification state and TTL.
  \item Correct the category, then repeat a similar sentence to demonstrate feedback retrieval.
  \item Open an insight and display the facts together with the persona's interpretive narrative.
  \item Turn off the provider or Redis in a controlled manner to demonstrate that the fallback does not generate mock data.
  \item Do not present auth, bank sync, push notification, PDF, or backup as completed features when acceptance conditions have not been met.
\end{enumerate}

\chapter{Stabilization Criteria for Critical Functions}

Post-report bug-fix priorities are determined by impact on data and on academic demo capability:

\begin{enumerate}
  \item \textbf{P0 --- data integrity:} transactions do not leak connections, pending confirmation is atomic, batch rollback is correct, IDs are user-scoped.
  \item \textbf{P1 --- input pipeline:} the amount parser is correct, the provider selector reflects the correct state, clarification and history maintain a stable order.
  \item \textbf{P1 --- algorithms:} the timeline preserves months with no data, runway handles days with zero spending, reports use the correct denominator for the filtered period.
  \item \textbf{P2 --- tasks and media:} recurring payments are atomic, the worker deduplicates, adapters return real errors backed by ground truth.
  \item \textbf{P2 --- demo support:} wallet creation on a fresh install, export in the correct format, and backup/restore without retaining secret keys in the bundle.
\end{enumerate}

Every fix must have a regression test that fails before the fix and passes after the fix. Only a feature with both an automated test and a reproducible demo flow may move from ``target design'' to ``measured''.
